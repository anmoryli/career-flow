## 使用网页任务完整输入复现

沿用任务 36 已提交给 Qwen 的完整输入，只请求原 Qwen 接口，不调用 DeepSeek，不记录简历正文，不改写原用户的历史任务。

2. 修正统计后，完整输入又复现“简历证据未找到”：模型改写或拼接 evidence，违反现有逐字证据规则。

## 修复

- 对 SiliconFlow 已知接口启用 PydanticAI `openai_continuous_usage_stats`，读取最终累计用量，保留用量有效性校验，不调高上限绕过错误。读取超时、整次截止时间保持已有实现。
- 构建服务端证据目录：J 编号来自 JD 原文，E 编号来自简历或未跳过的回答，T 编号来自允许优化的原文位置。模型只返回编号；服务端恢复逐字证据、path 和 original，再执行原有 DiagnosisOutput 和业务校验。
- 不接受不存在的引用，不丢弃错误条目伪装成功，不放宽证据、维度或评分校验。最终 API 与已存结果格式保持不变。
- 输入快照记录 output_contract_version=diagnosis-references-1。无数据库迁移、无新增依赖。

参考：https://pydantic.dev/docs/ai/api/models/openai/ （openai_continuous_usage_stats 明确说明累计用量必须取最终值，不能逐块相加）。
