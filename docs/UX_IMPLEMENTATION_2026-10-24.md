# V1 交互闭环实现

按简历 → 岗位 → 诊断/费用 → 工作台顺序扩展既有单体，保留技术栈、三套简历宏与个人记录，不复制第三方主题。

## 简历与岗位

- `resumes` 记录所属人、当前版本和来源；`resume_versions` 保存不可变文档/排版快照。JSON 仅承载文档，所属权、版本、岗位、任务有独立表与外键。
- 自动保存通过 revision 检查冲突，UUID 防重复；失败保留页面，冲突可另存新简历或下载本地备份。
- 经历/项目/教育可新增、上下移、确认删除；最后一条可清空。模块显示开关不删除内容。照片、模板、字号、强调色、取景与版本一起保存。
- 历史可载入后保存新版本。打印页固定到指定快照；PDF 由浏览器 A4 打印生成。
- PDF 在受限 RQ 任务提取文字，先核对再保存；原始二进制在成功/失败后删除。扫描件明确报未支持。
- JD 保存到岗位并关联不可变简历版本；来源链接只记录、不抓取。

## 诊断与费用

- 每个诊断有持久化对话、回答、轮次、任务和结果；最多十轮、每轮一个问题、跳过计数，报告后对话只读。
- PydanticAI 只注册输出协议，不注册 SQL、Shell、文件或网络工具；输入包装为不可信 JSON，照片不发送给文字模型。
- 校验五维唯一性、分数、JD/简历/回答原文及建议字段白名单。用户可编辑、选择建议，核实后保存副本。
- 状态 `quoted → queued → running → succeeded/failed/cancelled`，确认前不冻结。成功按实际 Token 结算，释放剩余；无用量、无效输出、超时最多尝试两次，最终失败全额释放。
- 用户行锁、MySQL 当前读、任务/流水唯一键防止认证旧快照、重复确认和重复 worker 导致多次调用或结算。等待模型期间无数据库事务。
- 取消忽略迟到结果；Worker 维护及 `flask recover-stale-tasks` 回收中断任务。
- 积分初始零，仅非生产 CLI 可显式发放并记账；没有前端自助发放或真实支付。

## 界面与验证

- 工作台、报告、账本读取真实数据；注册单邮箱、重发倒计时、密码显隐、字段错误、失败保留输入。
