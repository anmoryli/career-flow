# 职序简历与岗位分析交互设计稿

状态：已按用户确认实施（核心简历、诊断、计费和保存规则保持原样）

## 设计边界

- 保留职序现有的简历、模板、AI 润色、PDF 导入、岗位分析、积分确认和报告流程。
- 保存当前简历时继续更新同一份简历；首次保存才创建记录。
- AI 生成内容先供用户核对，用户确认后才写入简历。
- 只调整页面入口、布局和控件表达，不增加新的工作台、向导体系或评分概念。
- 页面文案只说明用户正在做什么，不展示实现、解析规则或内部状态细节。
- 求职用户端采用顶部主导航与任务型首页；管理后台继续使用独立后台导航，避免将求职准备过程包装成运营控制台。

## 主流产品交互观察

1. **入口先解决“从哪里开始”**：Teal 把上传简历、粘贴文字和空白开始放在同一入口；导入后把内容放进分区字段，左边编辑、右边预览。[Teal 导入与粘贴流程](https://help.tealhq.com/en/articles/9457699-import-existing-resume-or-linkedin-profile)；[Teal 简历编辑器说明](https://www.tealhq.com/post/how-to-edit-resume-in-pdf)
2. **编辑按简历板块推进**：Rezi 使用简历板块标签，AI 写作建议贴近经历、项目等字段；用户可以逐项应用建议，实时看到预览变化。[Rezi AI Bullet Points](https://www.rezi.ai/rezi-docs/ai-bullet-points)
3. **AI 是字段旁边的工具**：Kickresume 在当前板块提供写作建议；生成后可以编辑内容或单独重写某段，不要求用户先学习另一套聊天流程。[Kickresume 简历编辑器](https://www.kickresume.com/en/help-center/resume/)
4. **自定义模块要靠明显入口，排序要有明确手柄**：Kickresume 把“新增板块”和“拖动调整顺序”放在内容编辑过程中，并允许直接重命名板块。[Kickresume 新增与排序板块](https://www.kickresume.com/en/help-center/resume/)
5. **岗位匹配保持一个清楚的输入和结果链路**：Teal 将岗位描述与简历匹配，给出关键词与内容建议；Rezi 在编辑板块中提供岗位相关建议，并在预览阶段呈现整体检查。[Teal 岗位匹配流程](https://www.tealhq.com/tools/resume-builder?via=browsingai)；[Rezi 实时分析](https://www.rezi.ai/rezi-docs/real-time-content-analysis-explained)

这些观察用于页面交互参考，不引入对方产品的评分规则、多个简历副本或额外工作区。

## 简历入口

用户打开“我的简历”后，只看到简历本身和三个清楚的开始方式：

```text
我的简历                                           [导入 PDF]

┌──────────────────────┐ ┌──────────────────────┐ ┌──────────────────────┐
│ 粘贴简历文字         │ │ 上传 PDF             │ │ 手动填写             │
│ 粘贴已有经历          │ │ 导入已有内容          │ │ 从空白开始             │
└──────────────────────┘ └──────────────────────┘ └──────────────────────┘

已有简历：  [姓名 / 目标岗位]                      [编辑] [岗位分析]
```

- 有简历时，“编辑”打开当前简历；“导入 PDF”把用户带到解析核对流程。
- 没有简历时，三个入口均可开始第一份简历。
- 粘贴与上传不在列表页堆叠表单；点击后进入对应的小型输入/解析界面，再进入编辑器。
- 导入结果先展示可修改字段。确认后回到同一份简历编辑，不在每次导入时悄悄增加列表记录。

## 简历编辑器

### 桌面布局

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 简历名称                         [清空] [导出 PDF] [保存]                │
├──────────────┬────────────────────────────┬─────────────────────────────┤
│ 板块导航      │ 当前板块                    │ 实时简历预览                 │
│              │                            │                             │
│ 基本信息      │ 姓名                       │                             │
│ 个人简介  ⋮  │ 目标岗位                   │          A4 页面             │
│ 工作经历  ⋮  │ 手机 / 邮箱 / 城市         │                             │
│ 项目经历  ⋮  │                            │                             │
│ 教育经历  ⋮  │                  [AI 润色] │                             │
│ 技能      ⋮  │                            │                             │
│ + 添加板块    │                            │                             │
└──────────────┴────────────────────────────┴─────────────────────────────┘
```

- 主体始终是“左侧板块导航、中央编辑、右侧预览”；不在编辑内容上方插入大段说明或样例说明。
- 左侧每个板块是一行：点击名称切换编辑内容。可排序板块右侧显示抓手 `⠿`，悬停提示“拖动调整顺序”；只拖抓手，避免误拖标签。
- 显示控制使用带文字的开关：`显示` / `隐藏`。不使用含义不清的勾号或加号。
- 隐藏板块保留在导航中，状态清楚标记为“隐藏”，点击“显示”即可恢复。
- `+ 添加板块` 打开轻量弹层：输入板块名称，点“添加”后立即打开该板块。数量和内容类型不再引入多层选择。
- 自定义板块内只提供板块名、正文、逐段 AI 润色和删除。正文进入模板预览与导出。
- 当前板块下方提供“AI 润色”。点击后沿用现有费用确认，再显示原文和建议；用户可“应用建议”或“保留原文”。AI 不直接覆盖内容。
- 保存按钮始终保存当前简历；状态只显示“保存中 / 已保存 / 保存失败”。不要在页面解释数据库版本或系统实现。
- 模板选择继续作为左侧的“模板”板块；更换后预览即时更新，不增加新的模板向导。
- 清空填写放在次级操作中，并保留现有二次确认，避免误触。

### 新建流程

```text
选择开始方式
  ├─ 粘贴文字 → 选择模板 → 费用确认 → 生成草稿 → 核对 → 应用到编辑器
  ├─ 上传 PDF → 解析 → 核对可编辑字段 → 选择模板 → 应用到编辑器
  └─ 手动填写 → 选择模板 → 编辑器
```

- 选择模板只出现一次：用户可在开始时选择，也可随时在“模板”板块更换。
- 粘贴文字生成草稿后，以字段列表呈现识别到的内容和缺失项；不把模型输出直接当成已确认事实。
- PDF 解析失败时保留原文件选择与明确错误，提供重试和手动填写入口。
- 无论从哪个入口进入，最终落在同一个编辑器和同一份当前简历上。

### 手机布局

- 板块导航做成可横向滚动的紧凑标签条；当前板块内容单独占满宽度。
- 顶部“编辑 / 预览”切换只用于手机，桌面继续并排显示。
- 排序除拖动外提供小型“上移 / 下移”操作，避免触屏设备无法拖动；不显示在桌面常规状态。
- AI 建议使用底部弹层，原文和建议上下排列，操作按钮固定在底部。

## 岗位分析

```text
岗位分析

简历       [当前简历 ▼]
岗位名称   [选填]        公司 [选填]
岗位描述   [粘贴完整岗位要求                         ]
           [字数]                         [开始分析]

结果：匹配概览
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 已体现项  │ │ 待补充项  │ │ 未提及项  │
└──────────┘ └──────────┘ └──────────┘
硬性要求 / 经历匹配 / 缺失信息
每条建议：[查看依据] [AI 润色] [应用到简历]
```

- 输入页只要求选择简历和粘贴岗位描述；公司、岗位名称、链接为轻量选填。
- 开始分析前保留现有费用确认。确认后显示进度，完成后进入结果页。
- 结果先给可解释的概览，再按硬性要求、简历已体现、简历未体现分组；“未体现”不等于用户不具备。
- 数字用简单条形图或环形图表达，颜色只区分“已匹配、待核实、未提及”，不再叠加多张无关卡片。
- 建议明确关联到简历板块。用户点击“AI 润色”后仍经过费用确认、原文对照、用户应用，不自动修改简历。
- 已完成报告保持现有只读规则；继续优化沿用现有版本逻辑，不在本设计中改变保存业务。

## 页面状态与反馈

| 操作 | 需要显示的反馈 |
| --- | --- |
| 保存 | 按钮短暂显示“保存中”，完成后显示“已保存” |
| AI 生成/润色 | 费用确认 → 处理中 → 建议对照 → 应用或保留 |
| PDF 上传 | 文件名与解析进度；失败后原输入保留并可重试 |
| 自定义板块 | 添加后立即可编辑；删除前确认 |
| 岗位分析 | 输入核对 → 费用确认 → 进度 → 分类结果 |
| 空白简历 | 直接显示编辑字段和模板，不插入虚构经历说明横幅 |

## 用户端导航与首页

- 登录后使用顶部导航在总览、简历、岗位、报告和历史记录之间切换；个人中心、会员与积分通过账户菜单进入。
- 首页只突出最近编辑的简历和下一步求职任务，不堆叠统计数字、快捷入口卡墙或运营看板。
- “整理简历 → 对照岗位 → 核对建议”作为轻量路径提示，用户可以直接进入任意已有内容。
- 页面宽度、表面颜色、边框、字体和交互状态沿用共享主题 token；手机端顶部导航可横向滚动，正文自然收为单列。
