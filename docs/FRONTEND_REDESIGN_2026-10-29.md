# CareerFlow V1 前端体验设计（2026-10-29）

> 历史阶段记录：当前入口与任务架构已进一步重构，请以 [Landing 架构](FRONTEND_LANDING_ARCHITECTURE.md) 为准。

当前设计以 dc2a2e0 的活动前端为基础继续调整。完整逐页问题与验收清单见 [前端体验审计](FRONTEND_EXPERIENCE_AUDIT_2026-10-29.md)，模块职责见 [前端架构](FRONTEND_ARCHITECTURE.md)。原有 `interface.css` 和旧工作台脚本不再参与活动页面。

## 统一方向

低饱和绿色用于当前状态、关键证据与行动提示，中性背景承载内容。通过明确的标题/正文/说明层级、版面比例和实际文档建立视觉重点；不堆叠渐变、大阴影和统计卡。共享 Token 定义 12px 辅助、13px 控件、15px 基础正文，页面标题 28–36px，展示标题按屏幕变化。模拟缩略图和 A4 排版使用独立尺寸，不随界面字号改变。触控设备主要控件至少 44px；危险操作和权限信息继续完整呈现。

## 页面与交互

- 首页：具体说明简历编辑、AI 改写与岗位准备；主行动进入真实编辑器。产品预览显式标识示例；模板展示与三个可键盘展开的工作过程说明取代重复的长段介绍。没有伪造模型任务或产品指标。
- 登录/注册/找回：表单优先，保留字段校验、验证码与登录后的原操作继续；找回页面明确邮件验证和新密码两步。
- 总览：大字号姓名、最近工作与真实进行中任务。主要行动按已保存简历/已有结果/进行中任务决定；三步准备路径由已有简历、岗位和结果推导，不把“有文件”当作内容质量评分。移除持续旋转的装饰轨道。
- 简历库/模板：文档名称、时间和下一步更易读；搜索显示数量、无结果可清除；选择模板后进入编辑器。
- 导入/核对：选择文件→提取核对→继续编辑，展示真实文件名与大小、格式错误和读取状态。无效格式留在本地，不上传；后端仍执行完整校验。
- 编辑器：保持全屏内容/设计/预览结构。顶部明确区分模板示例与本人内容；板块定位和字段焦点对应预览区域。AI 原文/建议并排比较，移动端纵向排列；采用必须由用户操作。保存、错误、并发冲突和原内容保护保留。
- 岗位分析：就绪步骤来自简历选择与岗位描述；明确提交期间、排队、运行和失败。错误就近对应字段，原始禁用限制在失败后保留。
- 诊断/追问：按真实任务阶段组织主要行动、结果、证据和补充内容；完成诊断只读，仍可核对建议并另存岗位版本。
- 段落审阅：原文、编辑内容和候选稿分明，支持已改动/已选择过滤，显示字数与保存数量；候选稿校验完成后才允许采用。
- 报告/历史/对话：以文档与内容为中心，搜索结果计数和清除条件有明确反馈；避免重复空状态，对话保存仍走原服务。
- 会员/设置：权益、周期、真实支付开放状态可读；个人信息、主题、安全与注销分组，保留危险操作确认与原服务端限制。
- 后台：总览、用户、订单、配置、审计共享上述 Token，表格在自身区域滚动；配置按分组保存，安全字段与激活权限保留。

## 动效与可访问性

共享入场由 IntersectionObserver 与 Web Animations 渐进增强，不以 CSS 预先隐藏内容。JS 不可用时正文仍可见；系统要求减少动效时不启动入场，并取消进行中的入场。状态样式只表示真实运行阶段，没有虚构百分比或循环播放成功步骤。编辑预览聚焦、按钮、展开和状态转换使用轻量反馈，打印不包含聚焦装饰。

保留跳转主内容、键盘焦点、弹窗原生焦点管理；服务端字段错误通过 `aria-invalid` 和 `aria-describedby` 关联提示，输入修正时清理对应错误。动态 AI 表单白名单、Markdown 安全渲染与 CSRF 不变。

## 变更边界

改动位于 `app/templates/frontend`、`app/static/css/frontend`、`app/static/js/frontend`、浏览器验收与本文档。Flask/Jinja/HTMX/Alpine/Tailwind 不变；未新增依赖、数据库迁移、业务 API 或计费变更。模型与支付仅使用既有测试提供器验收，不代表真实模型、真实支付或生产部署已验证。
